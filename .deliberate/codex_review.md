REVISE

The mechanism is directionally right, but the plan is not safe to implement as written.

**Findings**
1. **Velocity-delta overwrite in the proposed pass ordering.** Current coupling passes write `vel = vel_frozen + dv`, and `apply_drag_pred` folds that into `pred` afterward. Drag and buoyancy are currently separated by their own freeze/apply blocks in [mod.rs](/Users/cxc/Github/coffee-sim/src/solvers/xpbd/mod.rs:2324). If the plan runs `drag_*`, `buoyancy_*`, then `impact_*` before one `apply_drag_pred`, the later pass can overwrite earlier deltas for the same species. Revise U3 to either apply/freeze between mechanisms, combine coupling deltas in one pass, or make later passes explicitly accumulate onto live `vel` while still deriving the symmetric pair scalar from `vel_frozen`.

2. **Momentum conservation needs a stricter implementation contract.** A `v^2` gate can be exactly momentum-conserving to fp tolerance, but only if both sides compute the same canonical pair. Add a shared WGSL helper taking `(water_i, grain_j)` and defining `n = normalize(x_grain - x_water)`, `v_rel = v_water - v_grain`, `approach = max(dot(v_rel, n), 0)`. Both `impact_grain` and `impact_water` should call that helper with canonical roles. Do not duplicate sign logic in two passes.

3. **The impulse/mass-split formula is underspecified and likely dimensionally wrong.** The plan says `J` is an impulse, then says grain gets `J * m_w/(m_w+m_g)` and water gets `-J * m_g/(...)`. For conservation, specify either `Δv_g = +I / m_g`, `Δv_w = -I / m_w`, or define a drag-style velocity impulse `Δv_g = +s * m_w/(m_w+m_g) * n`, `Δv_w = -s * m_g/(m_w+m_g) * n`. Also state where `dt` enters. Without this, “reduced-mass split” is ambiguous and easy to implement as non-conserving.

4. **Approach-only + `v^2` is not enough to protect percolation.** A downward percolating column does approach grains below it, and many small pair impulses across many neighbors/subiters can integrate into a real extra resistance. Do not defer the threshold/surface question. Add an upfront smooth threshold such as `smoothstep(v_impact_min, v_impact_full, approach)` calibrated above normal drawdown speeds, and require a percolation A/B gate before enabling web calibration. Surface restriction may be optional, but the threshold should be in U2, not follow-up.

5. **Hydrostatic no-creep needs noise gating, not just `v≈0`.** Saturated beds have solver jitter, wake/dead-band interactions, and residual PBF motion. A quadratic term suppresses small velocities, but does not make them zero. Require an approach threshold plus a per-particle or per-pair impulse floor/soft knee, and assert the impact pass alone produces zero-or-deadband motion on a saturated no-pour scene.

6. **A new dynamic-pressure term is justified, but the plan should narrow the claim.** Drag is linear, capped, and neighbor-count diluted; de-diluting it would likely increase packed-bed resistance and hurt drawdown. Buoyancy is pressure-gradient/flotation-oriented and can cause static creep if strengthened globally. However, the plan should explicitly reject an “impact-gated buoyancy/lambda pressure” variant only after noting why it cannot recover lost jet momentum after PBF redistribution. That makes the additive dynamic-pressure term a tested choice, not just an assertion.

7. **Stability mitigation is too weak.** `max_speed` in finalize is not a sufficient guard because `apply_drag_pred` uses the unclamped `vel - vel_frozen` to move `pred` before finalize. Add an explicit per-pair or per-particle impact cap before `apply_drag_pred`: for example limit normal relative-velocity reversal per subiter, cap `|Δv|` to a fraction of `h/dt_sub`, and relax the impact scale per subiter. The “eruption” test should inspect pre-finalize displacement or max `pred` jump, not only final speed.

8. **Running impact every drag subiteration is risky unless the plan defines relaxation.** Recomputing a quadratic force inside the Jacobi velocity subcycle can overshoot and oscillate around the approach/separation boundary. If it runs per subiter, scale it by subiter count or clamp by remaining normal approach. Alternatively run one impact block per substep after drag/buoyancy with its own freeze/apply. The plan must choose one.

9. **No-new-buffer/default-off is sound, with a layout caveat.** Reusing the existing drag/buoyancy binding set is the right call. For `Params`, use the existing `_pad_coupling0` slot or update both Rust/WGSL layout plus the `size_of::<Params>()` assert in [mod.rs](/Users/cxc/Github/coffee-sim/src/solvers/xpbd/mod.rs:111). “Default 0 byte-unchanged” is only credible if `impact_scale == 0` skips dispatch entirely and layout tests prove no field shifted.

10. **The test suite needs more gates than crater/no-crater.** Keep the two-sided crater test, but add: impact-pass-only momentum conservation; approach/separation sign tests; `v^2` ratio test; percolation and ponding A/B tolerances; saturated no-pour no-creep; bounded pre-finalize `pred` displacement; and an overwrite-regression test proving drag + buoyancy + impact all contribute when enabled together. The crater test should fail both when `impact_scale = 0` and when the sign is flipped.
