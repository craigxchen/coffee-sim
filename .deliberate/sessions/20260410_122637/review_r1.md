REVISE

1. The `substeps: 5 -> 3` recommendation is not justified by the current timestep logic, and the CFL math in the plan is wrong. [`step_frame`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L267) clamps `dt` to `1/30`, not `1/60`, so with `dx = 14 / 64 = 0.21875` and `v_cap = 30`, `substeps = 3` gives a worst-case CFL of about `1.52`, while the current `5` substeps are about `0.91`. With physics already described as unstable, this should not be the first optimization. Make substeps adaptive, or keep `5` until the safe, semantics-preserving wins are measured.

2. Replacing `bed_lookup_clear` with `encoder.clear_buffer()` is incorrect as written. [`bed_lookup_clear`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L1368) initializes empty cells to `-1`, and [`bed_lookup_scatter`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L1381) relies on `atomicMax` over that sentinel. Zero-filling would make untouched cells look like they contain bed particle `0`, which would corrupt absorption and any other bed-lookup consumers. `clear_buffer()` is fine for [`grid`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/state.rs#L105) and [`grid_vel`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/state.rs#L112), but not for `bed_lookup` unless the buffer type/sentinel scheme is redesigned.

3. The proposed `grid_update` early-exit is effectively a no-op. The expensive absorption path is already guarded by `if mass_w > 1e-6 && mass_s > 1e-6` in [`grid_update`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L712), so the arrays and 27-neighbor scan are not running on every cell today. That item should be replaced with a real optimization, such as a true empty-cell early return after zeroing the buffers, or a cheaper bed-occupancy mask to avoid the 27-cell lookup when mixed cells are sparse.

4. The plan targets `boundary_project`, but it misses a comparable or larger static-geometry hotspot in `classify_cells`. [`boundary_project`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L1097) does expensive SDF work on every cell, so the empty-cell early return is good. But [`classify_cells`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L823) also samples the same static SDF over the dense grid, and for fluid cells it does up to 7 SDF probes. Since the cup SDF is static, the plan should at least consider precomputed per-cell solid/boundary metadata; otherwise you are only trimming one of several dense SDF passes.

5. Reducing `PRESSURE_RBGS_PAIRS` from `20` to `12` is a plausible tuning knob, but it is not a free optimization and should not be bundled with substep reduction as if both were semantics-preserving. The current solver loop is in [`mod.rs`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L357). Make this runtime-tunable and A/B it after the safe changes; otherwise if pressure quality regresses, you will not know whether the cause was fewer substeps, fewer RBGS iterations, or both.

6. The testing plan is too coarse for a GPU performance regression. Timing `step_frame` over 100 frames is useful, but it will not tell you which pass improved or whether the dual-grid regression is coming from bed-specific work versus dense grid sweeps. There are already separate bed/no-bed presets in [`benchmark_free_stream`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L140) and [`benchmark_center_pour`](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L149); use both, and add per-pass GPU timing or capture-based profiling before and after each change.

The plan has good instincts, but it mixes safe GPU-budget reductions with physics-altering numerical shortcuts, and one of the proposed optimizations is based on a false reading of the current shader. I would re-scope it into two phases: first, safe wins (`boundary_project` early-out, `clear_buffer` for zero-only buffers, pass-level profiling); second, controlled solver tuning (`RBGS` count, possibly adaptive substeps). The medium-term architectural fix is to stop paying dense-grid SDF cost every substep for static geometry.
