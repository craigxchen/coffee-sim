REVISE

The plan is directionally good. It correctly identifies real hotspots in `classify_cells`, `boundary_project`, the full-grid clears, and the fixed 20 RBGS pairs. But it is not ready to implement as written because one of the main Phase 1 changes conflicts with the current resource budget, and the profiling section is not actionable enough to validate the wins cleanly.

1. The proposed `sdf_class` storage buffer is not viable as written. The pipeline currently hard-caps the shader stage at 10 storage buffers in [mod.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L31) and [mod.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L38), and the bind group is already using that budget in [pipelines.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/pipelines.rs#L27) through [pipelines.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/pipelines.rs#L75). There is also an explicit validation test for this limit in [physics_tests.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/physics_tests.rs#L260). Specific guidance: do not add a new storage buffer bind as the plan suggests. Use a compact 3D texture for the cached mask, or reuse existing per-cell scratch/storage, or explicitly replace another binding and update limits/tests accordingly.

2. The profiling strategy needs revision. The current compute pass has no timestamp instrumentation in [mod.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L312), and “per-pass wall-clock over 200 frames” will not tell you per-pass GPU cost. It is also confounded by changing workload because both benchmark presets are time-evolving pours in [mod.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L140) and [mod.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L149). Specific guidance: either add GPU timestamp queries where supported, or benchmark whole-frame deltas with pass toggles after a fixed warm-up / steady-state window, and log active particle/fluid-cell counts alongside timings.

3. The `grid_update` fast path should be store-free on empty cells. Right now the proposed early return still writes `scratch_absorbed_idx` and both `grid_vel` slots, but those buffers are already zeroed by `clear_grid` in [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L540) through [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L553). The current expensive work starts after the mass loads in [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L677) and [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L688), while the final stores are in [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L791). Specific guidance: load water/solid mass first, return immediately when both are empty, and rely on the clear step for zero state. If you replace `clear_grid` with `encoder.clear_buffer()`, note that this also requires restructuring the current single compute pass starting in [mod.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/mod.rs#L308).

4. The “Phase 1 is semantics-preserving / visually identical” claim is too strong as written. `classify_cells` currently uses live `sample_sdf` at the cell center in [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L823) and for neighbor-solid checks in [shader.rs](/Users/cxc/Github/coffee-sim/crates/sim-wasm/src/mpm_3d/shader.rs#L895). A cached mask can be equivalent, but only if it uses the exact same cell-center convention and lifecycle. Specific guidance: keep the SDF-cache path behind an A/B toggle until you have a direct cell-by-cell equivalence test and required-limits validation.

What I would approve after revision:
- Keep the `boundary_project` empty-cell early exit.
- Keep the `clear_buffer()` replacement for `grid` and `grid_vel`.
- Keep the RBGS tuning split into a separate measured phase.
- Revise the SDF cache design to fit current binding limits.
- Tighten the benchmarking plan so it can actually attribute wins.
